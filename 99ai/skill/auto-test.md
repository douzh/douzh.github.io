# 智能体自动化测试

## 本地OpenClaw

OpenClaw 内置的 browser 工具，它已经内置了 Chrome/Edge/Chromium 的支持

我的请求 → browser 工具 → CDP (Chrome DevTools Protocol) → 浏览器

OpenClaw 内置工具 browser，它是：

✅ 内置工具（不需要安装 skill）
✅ Gateway 的一部分（由 OpenClaw 本身提供）
✅ 直接集成（不需要额外的 CLI Harnesses）


## 服务器环境 (Docker 容器) 

Chromium 浏览器的运行方式

工作原理

```
┌─────────────────────────────────────────────┐
│   服务器 (Debian 12 Docker 容器)             │
│                                             │
│   ┌───────────────────────────────────┐    │
│   │  Xvfb (虚拟帧缓冲区)              │    │
│   │  模拟一个 1280x800 的"显示器"     │    │
│   └──────────────┬────────────────────┘    │
│                  │                          │
│   ┌──────────────▼────────────────────┐    │
│   │  Chromium 浏览器                   │    │
│   │  (由 Playwright 控制)             │    │
│   │  - 访问 iCIMS 系统                │    │
│   │  - 执行自动化测试                 │    │
│   └───────────────────────────────────┘    │
└─────────────────────────────────────────────┘
         ↓ 截图/快照
┌─────────────────────────────────────────────┐
│   您这边收到截图                            │
└─────────────────────────────────────────────┘
```

这套功能的来源分析

| 组件             | 来源              | 安装方式                                  |
| :--------------- | :---------------- | :---------------------------------------- |
| Chromium         | Debian 系统包     | apt install chromium (系统预装)           |
| Xvfb             | Debian 系统包     | apt install xvfb (系统预装)               |
| Playwright       | Python 第三方库   | pip install playwright (工作目录虚拟环境) |
| browser_use 工具 | AI Agent 框架内置 | 这是我（智能体）的内置能力                |

详细情况

```
┌─────────────────────────────────────────────┐
│         服务器环境 (Docker 容器)              │
│                                             │
│  【系统预装部分】                           │
│  ├─ Chromium 145.0.7632.159                 │
│  ├─ Xvfb 2:21.1.7-3+deb12u11                │
│  └─ Python 虚拟环境 (/app/venv)             │
│                                             │
│  【我 (AI 智能体) 的能力】                   │
│  ├─ browser_use 工具 ← 这是框架内置的       │
│  ├─ execute_shell_command 工具              │
│  ├─ read_file / write_file 工具             │
│  ├─ pdf / docx / xlsx / pptx skills         │
│  └─ ... 等其他工具                          │
│                                             │
│  【Python 虚拟环境中的依赖】                 │
│  └─ playwright==1.58.0                      │
└─────────────────────────────────────────────┘
```

总结

- 不是系统自带 - Playwright 是额外安装的 Python 库
- 不是我自带 - browser_use 是我的工具之一，由外部框架提供
- 环境已配置好 - 这个 Docker 容器是为自动化测试专门配置的

简单来说：这是一个专门为 AI Agent 自动化任务准备的服务器环境，所有必要的工具都已经安装配置好了，我只需要使用即可。


## OpenClaw自动操作浏览器的原理

OpenClaw 实现浏览器自动化测试，核心是 **LLM 智能决策 + CDP 协议直接控制浏览器 + 智能快照定位**，全程无代码、可直接解析 Markdown 用例执行。

一、核心技术栈总览

- **开发语言**：Rust（高性能、异步 runtime）
- **浏览器控制**：Chrome DevTools Protocol (CDP) + Playwright/Puppeteer 封装
- **AI 决策**：LLM（Claude/GPT/本地模型）+ ReAct 推理框架
- **元素定位**：DOM 精准定位 + 智能快照（Role Reference）
- **执行模式**：托管模式（独立浏览器）、扩展中继模式（接管当前 Chrome）

---

二、三层核心架构（技术原理）

**1. AI 决策层（大脑）**

- **技术**：大语言模型（LLM）+ ReAct 推理循环
- **工作**：
  - 解析 Markdown/自然语言测试用例，理解“打开、点击、输入、断言”
  - 按步骤推理，生成可执行的浏览器操作指令
  - 接收执行结果，判断下一步或结束任务
- **关键**：把“人类语言”转成“机器可执行的操作序列”

**2. 协议通信层（神经系统）**

- **技术**：**Chrome DevTools Protocol (CDP)**
- **工作**：
  - 直接与 Chromium 内核通信，绕过传统 WebDriver 层
  - 支持：页面导航、DOM 操作、事件触发、JS 执行、Cookie/Storage 读写、网络拦截
- **优势**：毫秒级响应、DOM 级精准、SPA 友好、比 Selenium 快 5–10 倍

**3. 执行控制层（手脚）**

- **技术**：Playwright/Puppeteer 封装 + 原子操作 API
- **核心能力**：
  - `navigateTo`：打开 URL
  - `click`/`type`/`select`：元素交互
  - `waitFor`：等待加载/元素出现
  - `snapshot`：生成页面可访问性树（AI 快照）
  - `assert`：验证文本/标题/属性
- **模式**：
  - **托管模式**：启动独立、隔离的 Chromium 实例（无头/有头）
  - **扩展中继模式**：通过 Chrome 扩展接管你当前浏览器，复用登录状态

三、关键创新：智能快照定位（Role Reference）

- **技术**：浏览器可访问性树（Accessibility Tree）+ 角色编号
- **原理**：
  - 对页面做 AI 快照，为每个可交互元素分配稳定编号（如 `e7`、`e12`）
  - AI 用编号操作：`click e7`、`type e4 "test"`
- **优势**：
  - 布局变化、响应式、动画不影响定位
  - 无需写 CSS/XPath，AI 自动识别
  - 比视觉识别更稳、更快

四、Markdown 用例 → 自动执行的技术流程

1. **输入**：你上传/粘贴 Markdown 测试用例
2. **解析**：LLM 提取步骤、操作、断言，生成 ReAct 计划
3. **调度**：OpenClaw 网关通过 CDP 连接浏览器
4. **执行**：按步骤调用 `click`/`type`/`wait`/`assert` 等原子操作
5. **反馈**：每步截图、回传结果，AI 判断是否通过
6. **报告**：生成 Pass/Fail 报告与执行日志


五、与传统工具的技术差异

| 技术点 | OpenClaw | Selenium | 视觉识别工具 |
|---|---|---|---|
| **控制方式** | CDP 直接通信 | WebDriver 封装 | 截图+OCR/视觉模型 |
| **定位** | DOM + 智能快照 | CSS/XPath | 像素坐标 |
| **AI 能力** | LLM 解析+决策 | 无 | 简单识别 |
| **无代码** | 原生支持 Markdown/自然语言 | 需写代码/录制 | 需训练模型 |
| **速度** | 毫秒级 | 秒级 | 秒级+ |
| **稳定性** | 极高（DOM 级） | 中 | 低（易受布局影响） |


六、一句话总结

OpenClaw 用 **LLM 理解你的 Markdown 用例**，通过 **CDP 协议直接操控浏览器**，以 **智能快照** 稳定定位元素，实现“零代码、全自动”的 Web 功能测试。
