## 新建 kb-krr/64-ontology-zettelkasten.md（初为 74，用户要求改 64）

文章骨架：
1. 经典 Zettelkasten 的五个缺口（链接无类型 / 关系无性质 / 无一致性检查 / 无推理 / 标签无约束）
   → 「它是一堆裸 ABox，缺 TBox 与 RBox，且没有推理器」
2. Zettelkasten → 本体三盒对应表（编号 ≈ IRI、标签 ≈ 一元类断言、"每卡至少一链接" ≈ 基数约束）
3. TBox：三类笔记 + `FleetingNote disjointWith PermanentNote`；强调**类型不是文件夹**（多重归属 vs 单选）
4. RBox（收益最大）：`relatesTo` 父角色 + supports/contradicts/refines/derivesFrom/questions；
   **三条性质判断**：supports 不传递、contradicts 对称但不传递、derivesFrom 传递；
   **反直觉决定**：不要把 supports 与 contradicts 声明不相交（复合关系真实存在，会造假矛盾）
5. ABox：原子化；文献笔记「升格为个体」优于「降格为属性」（支持一对多）
6. 推理收益：传递闭包追溯来源谱系、逆关系反查被引、一致性检查、孤岛检测
7. Trilium 落地映射（无推理器 → 脚本模拟传递闭包/一致性/孤岛）
8. 能力边界：照 73 篇判定 —— serendipity 是弱涌现做不了，归纳入 ILP
9. 调和「无层级」与「有 TBox」：**卢曼的编号系统本身就是隐式 TBox**，TBox 不建笼子只把隐式规则写显
