# ATS 4.0 - AI 自主驱动的多愿景任务管理系统

## 🎯 一句话介绍

**ATS 4.0** 是一个让 AI 能够同时管理多个项目的智能任务系统，支持中断恢复、多 AI 协作和完整的工程文档体系。

---

## 🤖 这是什么？

想象你有一个超级助手（AI），可以同时帮你管理多个项目：
- **项目 A**: 开发一个 AI 助手
- **项目 B**: 搭建知识库管理系统  
- **项目 C**: 创建数据分析平台

ATS 4.0 就是帮助这个超级助手**有条不紊地工作**的系统，确保它：
1. ✅ 知道每个项目的目标是什么
2. ✅ 清楚当前正在做什么
3. ✅ 可以随时中断去做别的事，回来后能快速继续
4. ✅ 多个 AI 助手可以轮流或一起工作
5. ✅ 所有工作都有完整记录

## 📋 核心概念（通俗易懂版）

### 1. 愿景（Vision）= 项目目标

每个愿景就是一个独立的项目，例如：
- **V001**: "开发一个智能 AI 助手系统"
- **V002**: "搭建团队知识库管理平台"

每个项目都有自己的：
- 终极目标（为什么要做）
- 要解决的问题（有什么痛点）
- 具体目标（要做到什么程度）
- 任务清单（需要做什么）
- 执行计划（具体怎么做）

### 2. 五层架构 = 从抽象到具体的思考过程

```
我想做什么？(Vision)
  ↓
有什么问题？(Problems)
  ↓
要达成什么？(Goals)
  ↓
具体做什么？(Tasks)
  ↓
一步步怎么做？(Plans)
```

**记忆口诀**: Why → What's Wrong → What to Do → How to Do → Step by Step

### 3. 六类工程文档 = 工作记录本

在五层架构的每一层，都会同步生成对应的文档：

| 层级 | 文档类型 | 记录内容 |
|------|----------|----------|
| Vision/Problems/Goals | BRD（业务需求） | 为什么要做这个项目 |
| Vision/Problems/Goals | PDD（产品设计） | 产品长什么样 |
| Vision/Problems/Goals | AD（架构设计） | 技术架构如何设计 |
| Goals/Tasks | HLD（概要设计） | 系统模块如何划分 |
| Tasks/Plans | DD（详细设计） | 具体代码如何实现 |
| Goals/Tasks/Plans | DP（开发计划） | 时间和资源如何安排 |

### 4. 全局总览 = 项目仪表盘

像一个仪表盘，显示：
- 有哪些项目正在进行
- 每个项目的进度如何
- 资源（AI、时间）如何分配
- 项目之间有没有依赖关系

### 5. 上下文切换 = 工作中断与恢复

场景：AI 正在做 V001 的任务，突然需要处理 V002 的紧急问题

```
Step 1: 保存 V001 的进度（写下来）
Step 2: 切换到 V002（拿起 V002 的资料）
Step 3: 处理完 V002 后，回到 V001（查看笔记，继续工作）
```

## 🚀 快速开始（3 分钟上手）

### 第一步：创建第一个项目

```powershell
# 1. 进入 ats-4.0 目录
cd ats-4.0

# 2. 创建项目文件夹
New-Item -ItemType Directory -Path "visions/V001_my_project"

# 3. 复制项目模板
Copy-Item docs/templates/vision_template.md visions/V001_my_project/vision.md

# 4. 打开 vision.md，填写你的项目目标
```

### 第二步：分解项目

按照五层架构逐步细化：

```
1. 在 vision.md 中写下项目愿景
   ↓
2. 创建 problems.md，列出要解决的问题
   ↓
3. 创建 goals.md，设定具体目标
   ↓
4. 创建 tasks.md，分解为可执行的任务
   ↓
5. 在 plans/ 文件夹中创建执行计划
```

### 第三步：开始执行

```
1. 选择一个任务（从 tasks.md）
2. 创建对应的执行计划（在 plans/ 中）
3. 按计划执行，并在 progress/ 中记录进度
4. 完成后更新状态
```

## ✅ 核心能力（为什么选择 ATS 4.0）

### 1. ✅ 多项目并行管理

**能力**: 同时管理多个独立或关联的项目

**场景**: 
- 你有 3 个项目要做
- AI 可以根据优先级合理安排时间
- 项目之间有依赖关系也能处理

### 2. ✅ 随时中断与恢复

**能力**: AI 可以在任何时候中断工作，之后能快速恢复

**场景**:
- AI 正在写代码，突然发现需要先完善设计
- 停下来去写设计文档，完成后回来继续写代码
- 通过查看进度记录，5 分钟内完全接手

### 3. ✅ 多 AI 协作

**能力**: 多个 AI 可以轮流或一起工作

**场景**:
- AI-A 擅长架构设计，负责设计阶段
- AI-B 擅长编码，负责实现阶段
- 通过文档交接，无缝配合

### 4. ✅ 完整文档体系

**能力**: 自动生成并维护完整的工程文档

**好处**:
- 新 AI 可以通过读文档快速理解项目
- 人类可以随时了解进展
- 项目结束后有完整交付物

### 5. ✅ 灵活调整

**能力**: 计划可以随时调整，文档同步更新

**场景**:
- 做到一半发现更好的方案
- 更新计划，同步更新相关文档
- 所有变更都有记录

## 🎓 使用技巧

### ✅ 推荐做法

1. **项目命名**: 用 `V001_简短名称` 格式，如 `V001_ai_assistant`
2. **优先级**: 最重要的项目不超过 2 个（P0 级）
3. **定期更新**: 每周检查一次所有项目的进度
4. **记录依赖**: 如果项目 B 等项目 A 完成，一定要记下来
5. **少切换**: 尽量减少在不同项目间频繁切换

### ❌ 避免做法

1. ❌ 同时开启太多项目（建议最多 5 个）
2. ❌ 平均用力（优先保证重要项目）
3. ❌ 忽略项目间的依赖关系
4. ❌ 文档不及时更新

## 🔄 典型工作流程

### 新项目启动流程

```
1. 创建愿景文档 (vision.md)
   → 描述项目目标和价值
   
2. 创建问题文档 (problems.md)
   → 列出要解决的痛点
   
3. 创建目标文档 (goals.md)
   → 设定可衡量的目标
   
4. 创建设计文档 (BRD/PDD/AD)
   → 同步生成业务、产品、架构文档
   
5. 分解任务 (tasks.md)
   → 拆分成可执行的小任务
   
6. 创建概要设计 (HLD)
   → 规划系统模块
   
7. 制定计划 (DP)
   → 安排时间和资源
   
8. 开始执行！
```

### 任务执行流程

```
1. 从 tasks.md 选择一个任务
   ↓
2. 查看详细设计 (DD)
   ↓
3. 创建执行计划 (Plan)
   ↓
4. 执行任务
   ↓
5. 记录进度 (Progress)
   ↓
6. 更新设计文档 (如有修改)
   ↓
7. 完成任务，标记状态
```

### 中断恢复流程

```
1. 读取管理指南 (docs/guide/ats-portfolio-management.md)
   ↓
2. 查看 state.json，了解当前在做哪个项目的哪个任务
   ↓
3. 读取对应的进度记录 (progress/)
   ↓
4. 阅读相关文档（愿景、任务、设计等）
   ↓
5. 评估当前状态
   ↓
6. 继续执行或调整计划
```

## 📊 配置文件说明

### config.json - 系统设置

```json
{
  "multi_vision_system": {
    "enabled": true,        // 启用多项目管理
    "max_visions": 10,      // 最多支持 10 个项目
    "concurrent_execution": true  // 支持同时进行
  },
  "document_system": {
    "types": ["BRD", "PDD", "AD", "HLD", "DD", "DP"]  // 六类文档
  }
}
```

### state.json - 实时状态

```json
{
  "vision_portfolio": {
    "visions": {
      "V001": {
        "name": "AI 助手开发",
        "status": "active",    // 正在进行
        "priority": "P0",      // 最高优先级
        "progress": 35         // 完成 35%
      }
    }
  },
  "execution_context": {
    "current_vision_id": "V001",  // 当前在做 V001
    "current_task": "T005"        // 当前任务是 T005
  }
}
```

## 🎯 常见问题

### Q: 最多能同时管理多少个项目？

**A**: 技术上无限制，但建议：
- 最重要项目（P0）：1-2 个
- 重要项目（P1）：2-3 个
- 总计活跃项目：不超过 5 个

### Q: 如何处理项目之间的依赖？

**A**: 
1. 在每个项目的愿景文档中记录依赖关系
2. 在全局总览（hub/overview.md）中查看依赖链
3. 优先完成被依赖的项目

### Q: AI 如何快速接手一个项目？

**A**:
1. 阅读愿景文档（了解目标）
2. 查看配置文件（了解当前状态）
3. 阅读进度记录（了解执行情况）
4. 阅读相关设计文档（了解细节）
5. 5 分钟内完全理解并开始工作

### Q: 文档太多太复杂怎么办？

**A**:
1. 使用模板（docs/templates/ 中有所有模板）
2. 按需填写，不必追求一步到位
3. 随着项目推进逐步完善
4. AI 会自动维护和更新文档
