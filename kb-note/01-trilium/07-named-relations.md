# Trilium 命名关系（Relation）

Trilium 构建语义知识网络的核心是**原生命名关系（Named Relation）**——关系本身就是带语义属性的一等公民，而非普通的无差别双向链接。所有关系数据结构化存储在 SQLite 数据库中，支持自动双向同步、图谱可视化、条件查询，非常适合构建严谨的结构化知识库。

---

## 一、先分清：普通链接 vs 命名关系
Trilium 有两种本质不同的笔记连接方式，对应完全不同的用途：
- **普通内部链接**：语法 `[[笔记标题]]`，和 Obsidian 类似，仅用于正文跳转，属于文本级引用，没有结构化语义，无法按关系类型筛选。
- **命名关系（Relation）**：属于笔记的结构化属性，每条连接都有明确的关系名称（即你需要的“链接属性”），直接存储在 SQLite 的属性表中，支持自动双向维护、图谱可视化、批量条件查询，是构建语义知识网络的核心机制。

---

## 二、创建命名关系的3种方法
### 方法1：属性面板可视化创建（新手推荐）
这是最直观的方式，全程图形化操作：
1. 打开目标笔记，在右侧「自有属性」面板点击「+」号
2. 选择「添加关系」
3. 输入**关系名称**（如「作者」「发表期刊」「依赖组件」）
4. 选择目标笔记，确认即可完成创建
5. 勾选「可继承」可让子笔记自动继承该关系（适合分类模板场景）

### 方法2：快捷语法快速创建
在属性面板的输入框中直接输入 `~关系名=@`，会弹出笔记补全框，选择目标笔记回车即可快速创建：
```
~作者=@鲁迅
~发表期刊=@新青年
```
`~` 开头代表关系属性，`@` 后关联目标笔记，这是 Trilium 原生的快捷语法，适合键盘流高效操作。

### 方法3：关系图拖拽创建
在「关系映射图」笔记中，直接拖动笔记右侧的连接点到另一个笔记，输入关系名称即可一键创建，适合可视化梳理知识网络时边拖边建。

### 反向关系自动同步
Trilium 支持定义**反向关系名**，实现双向自动维护。例如定义「作者」的反向关系为「代表作品」，当给《狂人日记》添加「作者→鲁迅」的关系时，鲁迅的笔记会自动生成「代表作品→狂人日记」的反向关系，无需手动维护两端。

标准化的知识网络建议提前通过「属性定义」模板统一配置关系和对应的反向名称，保证语义一致性。

## 三、完整示例：现代文学语义知识库
我们沿用之前的场景，构建「人物-作品-期刊」三类实体的语义网络，所有关联均为带明确属性的命名关系。

### 1. 人物笔记：鲁迅
**标签（Label，普通元数据属性）**：
- `#实体类型=人物`
- `#出生日期=1881-09-25`
- `#职业=文学家,思想家`

**关系（Relation，语义化链接）**：
- `~代表作品=@狂人日记`
- `~代表作品=@孔乙己`
- `~代表作品=@药`
- `~任职机构=@北京大学`

设置反向关系后，添加这些关系时，目标笔记会自动生成反向关联。

### 2. 作品笔记：狂人日记
**标签**：
- `#实体类型=作品`
- `#作品体裁=短篇小说`
- `#发表年份=1918`

**关系**：
- `~作者=@鲁迅`
- `~发表期刊=@新青年`
- `~所属文集=@呐喊`
- `~主题=@封建礼教`
- `~主题=@启蒙思想`

### 3. 期刊笔记：新青年
**标签**：
- `#实体类型=期刊`
- `#创刊年份=1915`

**关系**：
- `~主编=@陈独秀`
- `~主要撰稿人=@鲁迅`
- `~主要撰稿人=@胡适`
- `~收录作品=@狂人日记`
- `~收录作品=@文学改良刍议`

这样构建的网络中，每一条链接都有明确的语义，不再是模糊的“双向链接”，而是可以按「作者」「收录作品」「任职机构」等维度精准筛选的结构化关联。

## 四、语义网络可视化
Trilium 原生提供两种图谱视图，分别对应不同使用场景：

### 1. 笔记图谱（Note Map）：自动生成全局关联网络
新建「笔记图谱」类型的笔记，系统会自动渲染指定范围内所有笔记的关系网络：
- 支持按关系名称筛选显示/隐藏（通过 `#mapIncludeRelation` 标签指定要显示的关系）
- 提供力导向、层级、环形三种布局模式
- 适合宏观观察知识网络的整体结构、发现知识间的隐性关联

### 2. 关系映射图（Relation Map）：带关系名称的自定义图谱
这是 Trilium 最具特色的可视化能力，连线上会直接标注关系名称，支持完全手动拖拽排版：
- 新建「关系映射图」类型笔记，点击空白处添加笔记节点
- 拖动节点右侧的连接点到另一节点，输入关系名即可创建带标签的连线
- 支持自定义箭头方向、线条颜色，完全手动控制布局
- 适合制作专题知识图谱、流程关系图、实体关系图

## 五、进阶：单条关系挂载多个属性
如果一条关系需要附带多个维度信息（例如“鲁迅任职于北京大学”需要同时标注职位、任期、院系），单靠关系名称无法承载，Trilium 的标准解决方案是**中间关系实体法**：

1. 新建一个专门的关系笔记，例如「鲁迅-北京大学任职记录」
2. 给这个中间笔记添加标签和关系：
   - 标签：`#关系类型=任职`、`#职位=讲师`、`#任职开始=1920-08`、`#任职结束=1926-08`、`#所属院系=中国文学系`
   - 关系：`~关系主体=@鲁迅`、`~关系客体=@北京大学`
3. 在鲁迅和北京大学的笔记中，分别关联这条关系笔记

这种方式本质是标准的三元组建模（实体-关系-实体），单条关系可以附加任意数量的属性，适合构建深度结构化的专业知识库。Trilium 的笔记克隆功能可以让同一条关系在多个视图中展示，不产生冗余数据。

## 六、关系的查询与利用
1. **搜索语法**：可以直接按关系检索笔记，例如搜索 `~作者=@鲁迅` 会列出所有鲁迅作为作者的笔记，支持多条件组合筛选
2. **模板与脚本**：通过脚本 API 可以批量查询关系网络，自动生成索引页面（例如自动列出某作者的全部作品）
3. **AI 接入**：所有关系数据结构化存储在 SQLite 中，配合 Trilium 原生 REST API，可通过 MCP 适配器让 AI 精准读取语义关系，实现基于知识网络的深度问答

---

## 七、与你核心需求的匹配
- ✅ **SQLite 原生存储**：所有笔记、标签、关系、附件全部存在单个 `document.db` 文件中，结构严谨，备份迁移极方便
- ✅ **U盘便携即用**：官方便携版解压到 U 盘，整个语义网络随插随用，不写入系统盘
- ✅ **链接带语义属性**：原生支持命名关系，关系是一等公民，而非文件链接的附加属性
- ✅ **可视化能力强**：原生支持带关系名称的图谱，无需安装第三方插件
