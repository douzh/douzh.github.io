# 13 · 多端同步:U 盘、公司 Windows + 家里 macOS

[返回 Trilium 档案](README.md) | [便携配置(前置阅读)](12-portable-config.md) | [返回总览](../note-soft.md)

> Trilium 的同步模型是**客户端-服务器**(像 Git 之于 GitHub),不是**文件级同步**(像 Obsidian 之于坚果云)。理解这一点,所有方案就清晰了:要么"数据库跟着 U 盘走"(单实例轮换),要么"数据库放服务器,多端各自拉取"(真同步)。

## 一、先懂模型:为什么不能直接拷文件去同步

| | 文件级同步(Obsidian 模式) | 客户端-服务器(Trilium 模式) |
| --- | --- | --- |
| 数据形态 | 一堆 .md 文件 | 单个 SQLite(document.db)+ 附件 |
| 网盘/U盘互拷 | ✅ 天然支持 | ⚠️ 仅作"整库搬运",**不是同步** |
| 增量合并 | 由网盘做 | 由 Trilium 同步协议做(行级合并) |
| 双端同时编辑 | 网盘产生冲突副本 | 服务器仲裁,极少冲突 |

**官方明确不支持**把 `trilium-data` 目录放进 OneDrive/坚果云/Dropbox 等实时文件同步盘——SQLite 单文件被两端同时改动会直接损坏数据库。U 盘拷贝是安全的,但前提是遵守"单实例纪律"(见下)。

## 二、方案 A:U 盘随身库(单实例轮换,零服务器)

**适用**:公司 Windows + 家里 macOS,不想架服务器,一次只在一台机器上写笔记。

### U 盘目录布局(关键:一套数据,两个启动器)

```
E:\ (U 盘,格式化为 exFAT ← Windows/macOS 都可读写;NTFS 在 macOS 默认只读!)
├── trilium-win\            ← Windows 便携版解压包(Releases 下载 windows-x64.zip)
│   └── trilium.exe
├── trilium-mac\            ← macOS 便携版(macOS zip 解压)
│   └── Trilium Notes.app
└── trilium-data\           ← 唯一的数据库目录(跨平台通用,SQLite 与 OS 无关)
    ├── document.db
    ├── backups\
    └── ...
```

启动脚本(放 U 盘根目录,Windows 端 `start-win.bat`):

```bat
@echo off
start "" "%~dp0trilium-win\trilium.exe" --data-dir "%~dp0trilium-data"
```

macOS 端终端执行(或做成 .command 脚本):

```bash
open "/Volumes/你的U盘/trilium-mac/Trilium Notes.app" --args --data-dir "/Volumes/你的U盘/trilium-data"
```

> macOS 首次运行未签名应用:右键 App → 打开 → 确认(绕过 Gatekeeper),一次即可。

### 使用纪律(违反 = 数据损坏)

1. **同一时刻只开一个实例**——公司没退出就拔盘,家里又开一份,WAL 未落盘必坏库
2. **退出再拔盘**:File → Quit(或 Cmd+Q / 托盘退出),让 SQLite 完整刷盘
3. **每周把整个 `trilium-data` 拷一份到电脑硬盘**——U 盘会丢会坏,它不能是唯一副本
4. 公司电脑无管理员权限也不怕:Windows 便携版免安装,不写注册表

### 优缺点

- ✅ 零成本、零配置、离线可用、隐私最好(数据不过任何网络)
- ❌ 没有真正的"同步",只有"搬运";忘带 U 盘 = 今天没法记;双端同时有改动 = 手动二选一丢一边

## 三、方案 B:自建同步服务器(真正的多端同步,推荐)

**适用**:公司/家里/手机都要用,想随时记,自动合并。

### 第 1 步:架服务器(家里常开的电脑/NAS/VPS,Docker 一条命令)

```bash
docker pull triliumnext/trilium
docker run -d --name trilium \
  -p 8080:8080 \
  -v ./trilium-data:/home/node/trilium-data \
  triliumnext/trilium
```

浏览器打开 `http://服务器IP:8080`,首次向导:选语言 → 新建知识库 → **设一个密码(所有客户端都用它登录,务必记住,丢了不可恢复)**。

已有 U 盘库想迁上去?首次向导选"从备份恢复",或把 U 盘 `trilium-data` 整目录挂载进容器替换后再启动。

### 第 2 步:两端客户端接入

**公司 Windows**(装正式版或便携版皆可):首次启动向导选第三项 **"我已有 Trilium 服务器,要与它同步"** → 填 `http://服务器IP:8080` + 密码 → 自动全量拉取,本地留一份完整副本。

**家里 macOS**:同样操作(Homebrew:`brew install --cask trilium-notes`)。

事后改配置:Options(选项)→ **Sync(同步)** → 填服务器地址 → **Test** 测试连通,可设自动同步间隔(分钟级,默认开启)。

### 第 3 步:日常节奏

```
公司记笔记 ──自动推送──▶ 服务器 ◀──自动拉取── 家里 macOS 继续
                                │
                                └── 手机浏览器/PWA 打开同一地址直接用
```

- 每台客户端本地都有完整 SQLite 副本,**离线也能写**,联网后自动双向合并(同步是增量的,不是每次全量)
- 手机无原生 App,用浏览器/PWA 访问服务器即为移动版界面
- 手动即时同步:顶栏同步按钮(环形箭头)

### 没有公网 IP 怎么办

| 手段 | 说明 |
| --- | --- |
| **Tailscale**(推荐) | 公司/家/手机全装,组虚拟局域网,服务器地址填 Tailscale 内网 IP,免费、免公网、加密 |
| frp / cpolar 内网穿透 | 需一台有公网的跳板或付费服务 |
| 仅局域网同步 | 家里 NAS 跑服务器,人在家才同步;公司改动攒着,回家自动合并(Trilium 支持离线积累后同步) |

### 优缺点

- ✅ 真·多端实时同步、增量合并、手机可用、离线可写
- ❌ 需要一台常开设备;跨公网需解决可达性;多一层密码管理

## 四、方案 C:离线搬运(没有服务器也不一直带 U 盘)

利用 Trilium 自带机制做阶段性合并:

1. **整库备份/恢复**:U 盘拷 `trilium-data`(同方案 A 纪律)——适合整库搬迁
2. **导出/导入**:Note → Export(`.tar` ZIP,含子树)在 A 机导、B 机 Import——适合单棵子树搬运
3. 注意:导出导入是**覆盖式合并策略有限**,两边都改同一笔记时会以后导入的为准,慎用做"同步"

## 五、三方案对比

| | A · U盘随身库 | B · 自建服务器 | C · 离线搬运 |
| --- | --- | --- | --- |
| 成本 | 一个 U 盘 | 一台常开设备 | 零 |
| 实时性 | 无(物理搬运) | 分钟级自动 | 手动、阶段性 |
| 双端同时改 | ❌ 会覆盖/坏库 | ✅ 自动合并 | ⚠️ 后导入覆盖 |
| 手机 | ❌ | ✅ 浏览器/PWA | ❌ |
| 隐私/离线 | 最优 | 好(自托管) | 最优 |
| 上手难度 | 低 | 中(Docker+网络) | 低 |
| 适合 | 单人单时点记录 | 长期重度知识库 | 偶尔迁移 |

## 六、红线清单(违反任何一条都可能丢库)

1. ❌ `trilium-data` 放 OneDrive/坚果云/Dropbox 等实时同步盘
2. ❌ 同一 `trilium-data` 目录被两个 Trilium 实例同时打开(含 U 盘插着忘了退出)
3. ❌ 拷库/拔盘前不退出 Trilium(SQLite WAL 未刷盘)
4. ❌ 服务器密码丢失——无法找回,只能整库备份恢复到新服务器
5. ⚠️ 客户端与服务器**大版本保持一致**(都用 TriliumNext 同代版本,勿一头 0.61 一头 0.10x 混接)
6. ✅ 备份三处存放:服务器本地 + 定期 `docker cp`/复制 `trilium-data` 到外部 + 关键子树定期 Export

## 七、推荐组合

- **轻量个人**:方案 A(U 盘)+ 每周整库备份到两台电脑 = 90% 需求已覆盖
- **重度多端**:方案 B(家里 NAS/小主机 Docker + Tailscale)+ U 盘每月冷备 = 生产级
- **过渡期**:先用 A 跑起来,数据量大了再上 B——`trilium-data` 整目录可直接迁入服务器,**无需重新整理**
