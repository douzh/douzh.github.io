# 13.1 · Tailscale 详解:Trilium 多端同步的网络层

[返回 Trilium 档案](README.md) | [多端同步(主文档)](13-sync.md) | [返回总览](../note-soft.md)

> Tailscale 是 [13-sync.md](13-sync.md) 方案 B 中"没有公网 IP 怎么办"的首选答案。本文展开:它是什么、怎么工作、免费额度、在 Trilium 场景的完整落地步骤、国内网络注意事项与横向对比。

## 一、它是什么

Tailscale 是一个**零配置的异地组网工具**——把你在不同网络里的设备(公司 Windows、家里 macOS、NAS、手机)拉进同一个虚拟局域网(称为 tailnet),每台设备获得一个固定的 `100.x.x.x` 内网 IP,之后互相访问就像插在同一个路由器下:

```
公司 Windows ─┐                          ┌─ 家里 NAS(Trilium 服务器,100.101.1.10)
              ├─ Internet(加密隧道)─────┤
家里 macOS  ──┘                          └─ 手机(浏览器访问 100.101.1.10:8080)
```

对 Trilium 的意义:**同步服务器地址永远填 `http://100.x.x.x:8080`,不管设备的物理位置和网络怎么变**——公司 wifi、家里宽带、手机 5G,都是同一个地址。

## 二、工作原理(三层)

| 层 | 组件 | 作用 |
| --- | --- | --- |
| 协调层 | Tailscale 官网服务器 | 设备注册、身份认证(用 Google/GitHub/微软账号登录)、密钥交换。**只传握手元数据,不传你的笔记内容** |
| 数据层(优先) | WireGuard P2P 直连 | 通过 STUN 打洞,两端建立点对点加密隧道,**流量不经过任何第三方服务器**,速度≈带宽上限 |
| 兜底层 | DERP 中继 | 打洞失败时(严格 NAT/公司防火墙),经 Tailscale 中继服务器转发,仍端到端加密 |

基于 WireGuard 协议——目前最快、最现代的 VPN 技术,加密强度远超传统方案。

## 三、免费额度(2026-04 起)

- **设备数:不限**(此前 100 台)
- 用户数:6 人(家庭共享够用)
- 3 个 ACL 组、50 个标记资源、每月 1000 分钟临时资源
- 流量不限,核心功能全开放,无个人付费墙

## 四、在 Trilium 同步场景的落地(15 分钟)

### 第 1 步:注册

官网 tailscale.com 用 GitHub/Google 账号注册(免费)。

### 第 2 步:各设备装客户端并登录同一账号

| 设备 | 安装方式 |
| --- | --- |
| 公司 Windows | [下载安装包](https://tailscale.com/download/windows),托盘点 Log in |
| 家里 macOS | App Store 搜 Tailscale,或 `brew install --cask tailscale` |
| 家里服务器(NAS/Linux) | `curl -fsSL https://tailscale.com/install.sh | sh && sudo tailscale up`;群晖有官方套件 |
| 手机 | App Store / Google Play 搜 Tailscale |

### 第 3 步:查服务器 IP

管理后台 [login.tailscale.com/admin/machines](https://login.tailscale.com/admin/machines) 或服务器上执行 `tailscale ip -4`,得到如 `100.101.1.10`。

### 第 4 步:Trilium 填地址

两端客户端 Options → Sync,服务器地址填:

```
http://100.101.1.10:8080
```

手机浏览器/PWA 访问同一地址。**完事**——以后在任何网络下都能同步,无需公网 IP、无需端口转发、无需 DDNS。

### 加分项:MagicDNS

开启后可用设备名代替 IP,如 `http://myserver:8080`,换设备重装也不用手改地址。

## 五、国内使用注意

| 问题 | 说明 | 对策 |
| --- | --- | --- |
| 打洞失败走海外 DERP | 国内官方 DERP 节点缺,中继延迟可能 150ms+,速度掉到几百 KB/s | 自建国内 DERP(一台最低配云服务器即可,有实测自建后速度拉满);或两端开启 IPv6 提升直连率 |
| 什么情况打洞会失败 | 两端都是对称型 NAT(NAT4)时,原理上无法直连 | 用 NatTypeTester 测自家网络;移动宽带多为 NAT1 很容易直连 |
| 极客替代 | 不信任官方协调服务器 | 自建 Headscale(开源服务端)+ 自建 DERP,完全脱离 Tailscale 官方 |

**对 Trilium 同步的实际影响很小**:同步是增量的(每次只传改动行,通常几 KB),即使走中继,150ms 延迟也完全无感——延迟敏感的是远程桌面/看视频,不是笔记同步。

## 六、横向对比

| | Tailscale | ZeroTier | frp | cpolar/蒲公英 |
| --- | --- | --- | --- | --- |
| 上手 | 装完登录即用,零配置 | 要记 16 位 Network ID+后台审批 | 要公网 VPS+自己维护 | 付费服务 |
| 原理 | P2P 优先,DERP 兜底 | P2P 优先 | 纯转发 | 纯转发 |
| 国内体验 | 直连好/中继差(可自建 DERP) | 同样打洞,中继一般 | 取决于 VPS | 本土中继 30-50ms,最优但收费 |
| 适合 | **个人多端(本案)** | 二层桥接需求 | 有服务器爱折腾 | 不想动脑花钱 |

## 七、结论

Trilium 同步场景下 Tailscale 的优势组合是"**零配置 + 免费 + 端到端加密 + 流量不过第三方**",而它的短板(中继延迟)恰好被 Trilium 增量同步的小数据量抵消。若公司网络极端严格连 DERP 都拦,退回 [13-sync.md](13-sync.md) 方案 A(U 盘)或方案 B 的"仅局域网 + 离线积累"模式。
