# Trilium 最佳实践:本体方法论笔记法

[返回 Trilium 档案](README.md) | [返回总览](../note-soft.md)

> 用 Trilium 做笔记的最佳方法:**把整个笔记库当作一个本体(Ontology)来经营**——先设计概念体系(类与谓词),再积累个体事实,让笔记从"文件夹"变成"可查询的世界模型"。本页是方法论总纲,细节在 03-12 各专题文档。

## 一、核心思想:三层分离

本体方法论的第一原则是 **TBox / ABox 分离**(详见 [06-ontology-tbox-abox.md](06-ontology-tbox-abox.md)):

```
你的 Trilium 库
├── 📖 字典区(TBox:模式层)——类定义、谓词定义、学科体系
│   ├── 模板笔记:人物/作品/读书笔记/日记……
│   └── 谓词表:作者/推导自/类比于……
├── 📄 内容区(ABox:数据层)——个体笔记及其属性断言
└── 🔧 自动化区——脚本、保存搜索、视图
```

| | 字典区 | 内容区 |
| --- | --- | --- |
| 内容 | 类模板、字段定义、谓词规范 | 具体笔记(书/人/事/公式) |
| 变更频率 | 低(设计期想清楚) | 高(日常只管积累) |
| 类比 | 数据库 schema、面向对象的类 | 数据行、对象实例 |
| 笔记数量 | 十几条 | 成千上万条 |

**收益**:模式稳定则数据干净;字段定义改一处、全部实例即时生效(类比 ALTER TABLE);SQL 检索永远可用。

## 二、建库五步法

### 第 1 步:设计类体系(想清楚再动手)

先回答"我的知识世界里有哪些**类**":
- 读书库:书籍、作者、出版社、主题
- 科研库:论文、概念、公式、人物、机构
- 日记库:日记、人物、地点、事件

**判断标准**:会在多条笔记间**建立关系**的名词才配成为类;只作字段值的(如"页数")用标签即可。

每类建一条模板笔记(详见 [05-templates.md](05-templates.md)),挂字段定义:

```
📖 书籍模板
  #label:书名=text,promoted
  #label:出版年=number,promoted
  #label:genre=enum(小说,散文,诗歌),promoted
  #relation:作者=promoted
  #relation:属于系列=promoted
```

### 第 2 步:设计谓词表(关系先命名再使用)

谓词是知识网络的"动词"。**不命名的关系就是死链**——[[链接]] 只能跳转,`~作者` 才能查询。建立谓词规范:

| 谓词 | 定义域 | 值域 | 逆谓词 |
| --- | --- | --- | --- |
| 作者 | 作品 | 人物 | 代表作 |
| 推导自 | 公式 | 公式 | 推导出 |
| 类比于 | 任意 | 任意 | (对称) |
| 属于系列 | 书籍 | 系列 | 收录 |

谓词设计参考 [08-formula-relations.md](08-formula-relations.md)(数学物理谓词表)与 [07-named-relations.md](07-named-relations.md)(创建方法与反向关系配置)。

### 第 3 步:建分类骨架(可选但推荐)

挂靠外部标准分类(如 GB/T 13745 学科体系)给知识一个公共坐标系,详见 [09-subject-classification.md](09-subject-classification.md)。要点:分类节点本身也走 TBox 思路——模板 + code 标签 + 脚本批量建树。

### 第 4 步:日常积累(ABox 填充)

- **新建笔记 = 实例化一个类**:在对应子树新建(父节点挂 `#template` 可继承),表单自动出现,填值即积累
- **正文自由,结构入库**:正文照常写散文;**结构化信息一律走 promoted 表单**,不埋在正文里
- **关系随手挂**:提到相关笔记就用 `~谓词=@目标`,而不是 [[]]——前者可查询,后者只是文本
- **一层记一事**:一条笔记只做一个"个体",复合内容拆成多条 + 关系连接

### 第 5 步:消费(检索与视图)

结构化积累的全部回报在这一步:

```
保存搜索:#genre=小说 ~作者=@鲁迅           ← 鲁迅的长篇小说
SQL:递归 CTE 沿 ~推导自 上溯完整推理链       ← 公式谱系(见 08)
Collections 表格:书籍按出版年排序           ← promoted 字段即列
Relation Map:~map:作者                     ← 关系网络可视化
```

## 三、本体方法论六原则

| 原则 | 含义 | 反模式 |
| --- | --- | --- |
| 1. **先模式后数据** | 字典区先于内容区设计;类和谓词想清楚再积累 | 边写边造字段,三个月后同义字段满天飞(出版社/出版方/press) |
| 2. **一名一义** | 每个谓词、每个类只用一个名字;别名用 `alias` | 又挂 `~作者` 又挂 `~writer`,查询永远漏 |
| 3. **结构入属性,叙述入正文** | 可检索的走标签/关系,可阅读的走正文 | 把年份、人名埋在正文段落里,SQL 查不到 |
| 4. **关系优先于链接** | 语义连接用 `~谓词`,纯跳转才用 `[[]]` | 全库 [[]] 双链,图谱一团乱麻且不可查询 |
| 5. **个体原子化** | 一条笔记一个个体,复合概念用关系表达 | 一条笔记塞下整本书+作者生平+出版史 |
| 6. **开放演进** | TBox 允许重构:改名/加字段/迁移用脚本批处理(见 [10-scripting.md](10-scripting.md)) | 害怕改模式,将错就错到底 |

## 四、推荐库结构(综合示例)

```
📕 MyBrain
├── 📖 字典(TBox)
│   ├── 模板
│   │   ├── 📖 书籍模板、👤 人物模板、📄 论文模板、🧮 公式模板、📅 日记模板
│   ├── 谓词表(每谓词一条笔记,记录定义域/值域/逆词)
│   └── 学科分类(GB/T 13745 树,见 09)
├── 📄 内容(ABox)
│   ├── 📚 读书          #template=@书籍模板(可继承)
│   ├── 👤 人物          #template=@人物模板(可继承)
│   ├── 🧮 公式库        #template=@公式模板(可继承)
│   └── 📅 日记
├── 🔧 系统
│   ├── 保存搜索、Collections 视图、Relation Map
│   └── 脚本(码校验/逆关系同步/一致性检查,见 10)
└── 🗄 归档
```

| 正文里提到的概念要不要单独建笔记? | 会被多处引用/挂关系 → 建;一次性提及 → 不建 | — |
| 标签值该多细? | 能枚举就 enum,能数字就 number;自由文本是最后手段 | [04](04-attributes.md) |
| 学科码/分类怎么挂? | 标签码(检索)+ subject 关系(图谱)双轨 | [09](09-subject-classification.md) |
| 公式之间怎么连? | 谓词表:等价于/推导自/特例于/近似于…… | [08](08-formula-relations.md) |
| 换笔记工具会丢什么? | 树和正文可导出;**属性/关系是 Trilium 私有优势**,迁移前先导出为 Markdown+SQL 备份 | [03](03-db-design.md) |
| 怎么防模式腐化? | 一致性检查脚本 cron 巡检(缺字段/悬空关系/非法枚举) | [10](10-scripting.md) |
