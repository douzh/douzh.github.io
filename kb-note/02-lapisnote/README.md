## 二、存储方式

**范式:单文件数据库(SQLite)**

```
%APPDATA%/com.jdnotes.app/   # 默认,可在设置中改到任意路径(如 U 盘)
└── SQLite 主库
```

| 维度 | 说明 |
| --- | --- |
| 存储形态 | SQLite 数据库 |
| 数据路径 | 默认 `%APPDATA%`,**设置中可自定义**到 U 盘等任意位置 |
| 备份 | 复制 SQLite 文件 |
| 纯文本 | ❌ 二进制 |
| 迁移 | 导出 Markdown |
| 废纸篓 | 软删除标记,库内可恢复 |
| AI 读写 | MCP Server 直接暴露库的读写能力 |

**优点**:备份简单、SQLite 结构化(AI 可精确读写)、路径可自定义实现数据便携。
**缺点**:二进制不可 Git diff、锁定风险同 SQLite 系、生态新。

## 四、MCP 与 AI 接入(五款中最强)

**评级:T0 —— 唯一原生内置,零配置**

| 维度 | 说明 |
| --- | --- |
| 官方 MCP Server | ✅ **应用启动时自动在 `127.0.0.1:19230` 开启** |
| 自动注册 | ✅ **自动注册到 Claude Code**,无需任何手工配置 |
| 配置难度 | 零配置 |
| AI 可操作能力 | 直接读写笔记库 |
| 内置 AI 助手 | ✅ DeepSeek/OpenAI/Claude/Gemini/Ollama 多模型 |
| 本地模型 | ✅ Ollama 完全离线 |

**意义**:把 MCP 当一等公民设计(而非事后补丁):
- AI 客户端 → MCP Server → SQLite 笔记库,链路最短
- 天然适合"AI 代理直接管理笔记库"工作流:自动归档、自动整理、对话式检索
- 换机后程序装好即自动接管(MCP 自动注册),U 盘数据无缝衔接

**典型工作流**:
```
Claude Code(或兼容 MCP 客户端)
    ↓ MCP(127.0.0.1:19230,自动注册)
lapisnote SQLite 笔记库
    ↓ 直接读写
"帮我把今天的日记归档到 XX 标签" / "检索我关于 XX 的所有笔记"
```

## 五、便携支持

**评级:数据便携 + 轻程序(策略 B)**

| 维度 | 说明 |
| --- | --- |
| 官方便携版 | ❌(安装包形式) |
| 安装包体积 | **小(Tauri 2 + Rust)**,重装成本低 |
| 数据目录 | ✅ 可自定义到 U 盘 |
| 免安装跨机 | ❌ 程序需安装 |
| 系统写入 | 安装器会写系统,数据不写 |

**方案**:"数据便携 + 轻程序"路线——U 盘只挂 SQLite 数据库;每台机器装一次程序(包小负担低);程序装好后 MCP 自动注册,AI 无缝接管 U 盘数据。
