# Logseq 档案

[返回总览](../note-soft.md)

- 项目:https://github.com/logseq/logseq(MIT 开源)
- 定位:开源、本地优先、隐私优先的大纲式双链知识管理工具(Roam Research 主流开源替代)
- 一句话:**大纲块级记录流——以"块"为最小单位,Journal 日记流"先捕捉后整理",块引用原生最强之一**

核心设计原则:用户完全拥有数据——官方服务器永远不存储、不分析私人笔记;提供可选的端到端加密协作。

---

## 一、笔记功能

| 功能 | 支持情况 |
| --- | --- |
| 编辑范式 | **大纲块级编辑**(每行一个块,Tab/Shift+Tab 无限缩进嵌套) |
| 工作流 | **Journal 日记流**(默认进入当日日记页,无需预先建目录) |
| 任务管理 | ✅ TODO/DOING/DONE/LATER/NOW 关键字原生内置 |
| 双向链接 | ✅ 核心卖点 |
| 知识图谱 | ✅ 官方图谱视图原生内置 |
| 查询 | ✅ **Datalog 查询引擎**(按属性/标签/链接/任务状态批量筛选) |
| 白板 | ✅ Whiteboards(官方内置) |
| 每日笔记 | ✅(就是默认工作流) |
| 移动端 | ✅ 官方 App |
| 插件生态 | ✅ 插件市场(白板/看板/思维导图/任务管理等) |
| 同步 | 官方付费 E2E 加密同步;或自由搭配 Git/坚果云/任意网盘 |

**核心工作流——大纲块级 + Journal**:
- 每行内容是独立"块",可独立引用、嵌入、跨页面移动;修改源块后所有引用位置自动同步
- 打开默认进入当日日记页,`[[页面引用]]`、`#标签` 自动归类——"先捕捉、后整理"低门槛工作流
- Datalog 示例:"找出本月所有未完成的项目相关任务"

**短板**:非传统富文本编辑器,长文写作不如 Obsidian 顺手;索引加载在内存,超大库启动慢;以日期页面为主,纯文件夹管理弱。

## 二、存储方式

**范式:纯文本文件夹(Markdown / Org-mode)**

```
my-graph/                # 一个"图谱" = 一个文件夹
├── journals/            # 日记页(按日期一页一文件)
│   ├── 2025_07_08.md
│   └── 2025_07_09.md
├── pages/               # 常规页面([[引用]]自动生成)
├── assets/              # 附件
├── logseq/              # 配置
└── *.edn                # 索引缓存(可删,启动重建)
```

| 维度 | 说明 |
| --- | --- |
| 存储形态 | Markdown / Org-mode 纯文本 |
| 数据主权 | ✅ 通用纯文本,不会被平台锁定 |
| Git | ✅ 文本 diff |
| 迁移 | ✅ 零成本 |
| 同步 | 自由组合(官方同步/Git/网盘) |
| **索引机制(特殊)** | **启动时把全部文本加载进内存的 Datascript 图数据库引擎做索引**,缓存文件仅加速启动 |
| 大数据量 | ⚠️ 内存索引,数万页后内存与启动时间是瓶颈 |
| 开源 | ✅ MIT,可审计可二次开发 |

**注意**:主存储并非 SQLite(与 Trilium/lapisnote 的 SQLite 原生存储有本质区别)。

## 三、链接功能

**评级:L3-L4(块引用原生最强之一,属性语法可表达关系语义)**

**链接语法**:

| 语法 | 功能 |
| --- | --- |
| `[[页面名]]` | 页面双链(自动建页) |
| `((块ID))` | **块引用**(精确到段落,修改源块全局同步) |
| `#标签` | 标签(本质是页面,与 `[[]]` 等价) |
| `key:: value` | **属性语法**(页面顶部或块内) |

**属性表达链接语义**(关键能力):

```markdown
- 狂人日记
  类型:: 书籍
  作者:: [[鲁迅]]        ← 这条链接带"作者"语义
  发布年份:: 1918
```

- 在"鲁迅"页面反链区,可筛选出所有以"作者"属性关联的作品——**关系的语义化检索**
- 属性值可以是页面链接,构成(页面,属性名,页面)三元组
- Datalog 查询:"所有 作者=鲁迅 且 评分>4 的作品"

**能力边界**(官方自述):
- 原生知识图谱**不按关系类型着色/命名**——属性关系在图谱上不可见
- 链接本身无独立多属性扩展;一条关系 = 一个 `key:: value`,多属性需多条
- 结构化三元组建模能力**弱于 Trilium**

## 四、MCP 与 AI 接入

**评级:T2 —— 社区方案(可用但需验证)**

| 维度 | 说明 |
| --- | --- |
| 官方 MCP | ❌ |
| 社区路径 | logseq-mcp-server 等适配项目(基于 HTTP API 或直接读 Markdown 文件夹) |
| 能力 | 页面读写、块级检索、属性查询(视适配器实现,Datalog 能力可部分暴露) |
| 成熟度 | 依赖社区维护者,需实测 |
| 旁路方案 | ✅ **文件系统旁路:纯文本文件夹,AI 直接读写 Markdown** |

**两条路径**:
1. 社区 MCP 适配器(标准链路,成熟度待验证)
2. **文件系统旁路**(与 Obsidian 同理):数据是纯 Markdown,AI 无需 API 直接读写——最简单可靠

## 五、便携支持

**评级:数据便携极佳,程序需安装(策略 B)**

| 维度 | 说明 |
| --- | --- |
| 官方便携版 | ❌(Electron 安装版;社区有绿色包,官方未承诺) |
| 数据 | ✅ **图谱 = 任意文件夹**,拷走文件夹即带走全部数据 |
| 数据跨机 | ✅ 纯 Markdown/Org,插任何机器可直接读(即使没装 Logseq) |
| 同步自由 | ✅ Git/网盘任意组合 |
| 抗拔性 | ✅ 纯文本,最坏丢最近未保存修改(优于 SQLite 系) |

**方案**:U 盘只放图谱文件夹;每台机器装一次 Logseq;数据本身跨工具跨平台可读。

## 六、适用场景与总结

| 场景 | 匹配度 |
| --- | --- |
| 快速记录/碎片化捕捉 | ⭐⭐⭐⭐⭐ Journal 日记流 |
| 大纲式思考/任务拆解 | ⭐⭐⭐⭐⭐ 块级无限缩进 |
| 任务管理 | ⭐⭐⭐⭐ TODO 状态原生内置 |
| 块级引用/单一事实源 | ⭐⭐⭐⭐⭐ ((块ID)) 原生 |
| 开源可审计 | ⭐⭐⭐⭐⭐ MIT |
| 数据主权/纯文本 | ⭐⭐⭐⭐⭐ 与 Obsidian 同级 |
| 三元组建模 | ⭐⭐⭐ 属性语法可用,弱于 Trilium |
| 长文写作 | ⭐⭐ 大纲流不适合 |
| 超大库性能 | ⭐⭐ 内存索引瓶颈 |

> **总结:Logseq 是"大纲块级记录流"——两个原生:块引用原生最强之一(((块ID)) 精确到段落,修改源块全局同步)、任务状态原生内置(TODO/DOING/DONE);一个工作流:Journal 日记流(默认当日页 + [[页面]]/#标签 自动归类,先捕捉后整理);一个引擎:Datalog 查询(按属性/链接/任务状态批量检索)。属性语法(key:: value)可实现关系的语义化表达,但图谱不显示关系类型,三元组建模弱于 Trilium。纯 Markdown/Org 存储,数据主权与 Obsidian 同级;开源(MIT)、隐私优先。最适合:快速记录、大纲思考、任务管理、隐私敏感用户。**
