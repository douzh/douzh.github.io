## 二、链接能力分级

```
L1 单向链接(仅跳转)          → 传统 wiki
L2 双向链接(自动反链)          → Obsidian / Logseq / 思源核心区
L3 块级引用(段落粒度)          → Logseq / 思源 / Obsidian
L4 链接带属性(关系有语义)       → Trilium(原生)/ 思源(属性视图)/ Logseq(属性语法)
L5 关系作为一等公民(可查询的图)  → Trilium 关系系统 / 思源数据库视图
```

## 三、各工具链接机制详述

### 3.1 Trilium Notes —— 关系属性系统(链接即一等公民)

Trilium 的链接体系分两层:

**1. 普通链接**:笔记正文中插入内部链接(指向另一笔记),仅跳转用。

**2. 关系属性(Relation)—— 核心特色**:

- 每个笔记可挂任意属性,属性分两类:
  - `label`:键值对标量(如 `类型:: 书籍`、`评分:: 5`)
  - `relation`:**指向另一个笔记的带名链接**——这就是带属性的三元组!
- 结构等价于知识三元组:`(本笔记, 关系名, 目标笔记)`

```
示例:
笔记《狂人日记》
  ├─ label:  类型 = 书籍
  ├─ label:  发布年份 = 1918
  ├─ relation: 作者 ──► 笔记《鲁迅》
  └─ relation: 收录于 ──► 笔记《呐喊》
```

- **关系可查询**:用内置搜索语法(或 SQL)直接查图,如"所有作者=鲁迅的作品"、"所有被 ≥3 篇笔记引用的来源"
- **关系可视化**:关系图(Relation Map)按关系类型渲染,链接语义一目了然
- **链接本身带元数据**:关系是数据库记录而非正文文本,可挂额外信息

**评级**:L5。五款中唯一把"关系"作为数据库原生一等公民的工具,最接近 Palantir 式本体/知识图谱建模。

### 3.2 lapisnote

- 资料确认的组织方式:**标签系统 + 日历视图**为主
- 双链/块引用能力未在官方资料中确认,按"以标签组织为主,双链能力存疑"记录
- 若需知识网络建模,以当前资料看不占优(待实测验证)

### 3.3 Obsidian —— 双链 + 插件生态,但链接是"纯文本"

**原生链接语法**:

| 语法 | 功能 |
| --- | --- |
| `[[页面]]` | 页面双链 |
| `[[页面\|别名]]` | 带别名链接 |
| `[[页面#标题]]` | 链接到标题 |
| `[[页面^块ID]]` | 链接到块 |
| `![[页面]]` / `![[图片]]` | 嵌入(Transclusion) |
| `#标签` / `#嵌套/标签` | 标签 |
| `%注释%`... | — |

**反链面板**:每个文件下方自动列出"链接了本页的页面"及引用上下文,还有"未解析链接"(提到但未创建的页面)——发现知识空白点的利器。

**图谱**:全局关系图谱 + 单页局部图谱,节点可过滤/着色(按文件夹/标签),但**不区分关系类型**(所有链接长得一样)。

**关键局限**:
- 链接只是正文里的文本字面量,**链接本身不能带属性**——"鲁迅 --[作者]--> 狂人日记"这种语义关系无处安放
- 社区补位方案:**Dataview 插件**——在笔记里写内联字段(如 `作者:: [[鲁迅]]`),用类 SQL 查询聚合,可模拟三元组,但语法生僻、查询结果非原生视图

**评级**:L2-L3(双链+块引用成熟),L4 需 Dataview 插件补。

### 3.4 Logseq —— 块引用 + 属性语法,大纲流知识网络

**链接语法**:

| 语法 | 功能 |
| --- | --- |
| `[[页面]]` | 页面双链(自动建页) |
| `((块ID))` | **块引用**(精确到段落,核心特色) |
| `((块ID))` 修改源块全局同步 | 单一事实源 |
| `#标签` | 标签(本质是页面,与 [[]] 等价) |
| `key:: value` | **属性语法**(页面顶部或块内) |

**属性表达链接语义**(关键能力):

```markdown
- 狂人日记
  类型:: 书籍
  作者:: [[鲁迅]]        ← 这条链接带"作者"语义
  发布年份:: 1918
```

- 在"鲁迅"页面的反链区,可筛选出所有以"作者"属性关联的作品——**实现了关系的语义化检索**
- 属性值可以是页面链接,从而构成(页面,属性名,页面)三元组

**Datalog 查询**:按属性/链接关系/任务状态批量检索,如"所有 作者=鲁迅 且 评分>4 的作品"。

**能力边界**(官方说明):
- 原生知识图谱**不按关系类型着色/命名**——属性关系在图谱视图上不可见
- 链接本身无独立多属性扩展;一条关系 = 一个 key:: value,多属性需多条
- 结构化三元组建模能力**弱于 Trilium**(官方自述)

**评级**:L3-L4(块引用原生最强之一,属性可表达关系语义)。

### 3.5 思源笔记 —— 块级引用 + 属性数据库,结构化最强

**链接语法**:

| 语法 | 功能 |
| --- | --- |
| `[[文档名]]` | 文档链接 |
| `((块ID))` | 块引用(搜索式插入) |
| `((块ID "文本"))` | 带锚文本的块引用 |
| `((块ID *))` 等静态原型 | 动态/静态引用块 |
| 嵌入块 | 块嵌入(类似 Transclusion) |

**块级粒度**:任何块(段落/列表项/表格行)有全局 ID,引用、反链、提及(Mention)都以块为单位——五款中块级能力最精细。

**属性 + 数据库视图**(与 Trilium 关系系统呼应):
- 文档/块可挂属性(键值对)
- **属性数据库视图**:把带属性的文档聚合成表格/看板/日历/画廊,类 Notion Database——相当于把三元组变成可筛选、可分组、可多视图的"关系表"
- 反向链接面板 + "提及"检测(正文文字提及但未链接)

**评级**:L3-L5(块引用最强,属性数据库可做关系建模)。

## 四、"链接带属性"(三元组建模)专项对比

这是知识图谱式建模的关键需求(把笔记系统当知识库用):

| 工具 | 关系表达方式 | 关系可查询 | 关系可视化 | 三元组建模评级 |
| --- | --- | --- | --- | --- |
| **Trilium** | relation 属性(原生) | ✅ 搜索/SQL | ✅ Relation Map 按类型 | ⭐⭐⭐⭐⭐ |
| **思源** | 块属性 + 数据库视图 | ✅ 数据库筛选/分组 | ⚠️ 有限 | ⭐⭐⭐⭐ |
| **Logseq** | `key:: value` 属性 | ✅ Datalog | ❌ 图谱不显示关系 | ⭐⭐⭐ |
| **Obsidian** | 正文文本(无原生) | ⚠️ Dataview 插件 | ❌ | ⭐⭐ |
| **lapisnote** | 未确认 | ❓ | ❌ | ⭐(待验证) |

**结论**:要做"关系作为一等公民"的知识图谱式建模,**Trilium 最强**(relation 原生、可 SQL、可视化),**思源次之**(属性数据库视图),**Logseq 可用**(属性语法+Datalog),**Obsidian 需插件补位**。

---

## 五、一句话总结

> **链接能力五档分级(L1单向→L5关系一等公民)下:Obsidian/Logseq/思源主打 L2-L3(双链+反链+图谱,链接是页面/块间的"裸连接");Logseq 用 `key:: value` 属性语法把链接语义化(作者:: [[鲁迅]]),配合 Datalog 查询达到 L4;思源以最精细的块级引用+属性数据库视图达到 L4-L5;Trilium 的 relation 关系属性系统是唯一原生 L5——链接本身就是数据库记录,带名字、可挂元数据、可 SQL 查询、可在 Relation Map 按类型可视化,等价于(实体,关系,实体)三元组,最接近知识图谱建模。专项结论:需要把笔记系统当知识图谱用(关系带语义、可查询、可视化),选 Trilium(最强)或思源(数据库视图);重记录流网络选 Logseq;重生态与长文选 Obsidian,其链接局限(纯文本、不带属性)可用 Dataview 插件部分弥补。**
