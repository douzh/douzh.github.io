# 基于 Obsidian 属性机制的语义化知识关联网络

下面以「现代文学研究知识库」为完整场景，演示如何用 Obsidian 的属性机制构建**带语义属性的知识关联网络**，包含笔记模板、查询语句和图谱配置，可直接复制复用。

---

## 一、核心笔记的属性与语义链接示例
我们定义三类实体：**人物（作者）、作品、期刊**，通过自定义属性赋予每条链接明确的关系类型，而非无差别的普通双向链接。

### 1. 人物笔记：鲁迅.md
文件顶部的 YAML 属性区定义实体基础信息 + 语义化关系链接：
```yaml
---
实体类型: 人物
别名:
  - 周树人
  - 豫才
出生日期: 1881-09-25
职业:
  - 文学家
  - 思想家
代表作品:
  - "[[狂人日记]]"
  - "[[孔乙己]]"
  - "[[药]]"
任职机构:
  - "[[北京大学]]"
---

# 鲁迅
正文内容……
```
`代表作品`、`任职机构`就是带属性的链接——每条连接都有明确的语义，区别于正文里泛泛的 `[[狂人日记]]` 普通引用。

### 2. 作品笔记：狂人日记.md
```yaml
---
实体类型: 作品
作品体裁: 短篇小说
作者: "[[鲁迅]]"
发表年份: 1918
发表期刊: "[[新青年]]"
所属文集: "[[呐喊]]"
主题:
  - 封建礼教
  - 启蒙
---

# 狂人日记
正文内容……
```
这里的 `作者`、`发表期刊`、`所属文集` 本质是给链接打上了“关系标签”，让单向的文件连接变成了结构化的语义关联。

### 3. 期刊笔记：新青年.md
```yaml
---
实体类型: 期刊
创刊年份: 1915
主编:
  - "[[陈独秀]]"
主要撰稿人:
  - "[[鲁迅]]"
  - "[[胡适]]"
收录作品:
  - "[[狂人日记]]"
  - "[[文学改良刍议]]"
---

# 新青年
正文内容……
```

## 二、属性链接的核心价值：结构化查询（Dataview 插件）
普通双向链接只能靠人工浏览反向链接，而属性链接可以配合 **Dataview** 插件做条件筛选、批量统计，这也是构建知识网络的实用价值所在。

### 示例1：在人物笔记中自动列出全部作品
把这段代码放到「鲁迅.md」的正文里，会自动生成作品清单，新增作品时自动更新：
```dataview
TABLE 作品体裁 as 体裁, 发表年份 as 年份, 发表期刊 as 发表刊物
FROM "知识库/作品"
WHERE contains(作者, [[鲁迅]])
SORT 发表年份 asc
```

### 示例2：在期刊笔记中筛选特定体裁的收录文章
```dataview
LIST
WHERE contains(收录作品, this.file.link) AND 作品体裁 = "短篇小说"
SORT 发表年份 desc
```

### 示例3：全局按年份统计所有作品
```dataview
TABLE 作者 as 作者, 发表期刊 as 期刊
WHERE 发表年份 = 1918
SORT file.name asc
```

## 三、知识图谱可视化效果
### 1. 原生图谱：按实体类型区分颜色
Obsidian 原生图谱不支持在连线上显示关系名称，但可以通过属性给节点分组着色，直观区分实体类别：
1. 打开全局图谱视图 → 右侧筛选面板 → 「分组」
2. 选择按属性 `实体类型` 分组
3. 分别给「人物」「作品」「期刊」设置不同颜色

效果：人物节点红色、作品节点蓝色、期刊节点黄色，关联网络的结构一目了然。

### 2. 增强图谱：连线上显示关系名称
如果需要在边线上标注关系类型（如“作者”“发表于”），可安装社区插件 **Vassago**，支持为不同关系定义颜色、线型、箭头方向和反向关系：
- `作者` 关系：绿色实线，带箭头，反向关系为 `代表作品`
- `发表期刊` 关系：蓝色虚线，带箭头，反向关系为 `收录作品`
配置后图谱会直接显示关系标签，接近标准知识图谱的可视化效果。

## 四、进阶：单条链接挂载多个属性（中间笔记法）
如果一条关系需要附带多个维度的信息（比如“鲁迅任职于北京大学”，要同时标注职位、任期、院系），原生单值属性无法满足，标准解决方案是**将关系本身也做成一个笔记**，用中间笔记承载所有属性：

### 中间关系笔记：鲁迅-北京大学任职.md
```yaml
---
实体类型: 关系
关系类型: 任职
主体: "[[鲁迅]]"
客体: "[[北京大学]]"
职位: 讲师
任职开始: 1920-08
任职结束: 1926-08
所属院系: 中国文学系
---
```
然后在「鲁迅.md」和「北京大学.md」中都引用这条关系笔记即可。

这种方式实现了标准的三元组建模（实体-关系-实体），单条关系可以附加任意数量的属性，适合构建深度结构化的知识库。

## 五、能力边界说明
- ✅ 适合：轻量级语义关联、按关系类型筛选查询、实体分类可视化、个人知识体系梳理
- ❌ 不适合：十万级以上三元组推理、复杂图计算、原生关系边深度检索（这类场景更推荐 Trilium Notes 的原生命名关系，或专门的图数据库工具）
