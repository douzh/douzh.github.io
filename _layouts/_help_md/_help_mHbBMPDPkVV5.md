{"noteId":"_help_mHbBMPDPkVV5","content":"Trilium natively supports the following formats for both import and export.\n\n## Supported formats\n\n*   HTML:\n    *   This is the main format used by Trilium, where standard tags are used to represent basic formatting and layout (e.g. `<strong>`, `<table>`, `<pre>`).\n    *   Note that HTML is not a standardized format so some more specific features such as admonitions or <a class=\"reference-link\" href=\"#root/_help_hrZ1D00cLbal\">Internal (reference) links</a> might not be supported by other applications.\n    *   The notes can also be exported as [static HTML that can be used for web publishing](#root/_help_ycBFjKrrwE9p).\n*   <a class=\"reference-link\" href=\"#root/_help_Oau6X9rCuegd\">Markdown</a>\n    *   Most of the formatting is preserved, see <a class=\"reference-link\" href=\"#root/_help_rJ9grSgoExl9\">Supported syntax</a>.\n*   OPML (Outliner Interchange Format)\n    *   Supports both OPML v1.0 for plain text and v2.0 with HTML support.\n\nTo import from other applications such as OneNote, Notion and others, see <a class=\"reference-link\" href=\"#root/_help_ckZ2uNWQmVeX\">Importing data from other applications</a>.\n\n## Maximum import size\n\nVersions prior to v0.104.0 had an upload limit of 250 MiB that could be bypassed via a `TRILIUM_NO_UPLOAD_LIMIT` environment variable; with v0.104.0 this limit was removed.\n\nNevertheless, there is still a limit for the maximum size of a **single item** (whether it's a <a class=\"reference-link\" href=\"#root/_help_W8vYD3Q1zjCR\">File</a>, an <a class=\"reference-link\" href=\"#root/_help_0vhv7lsOLy82\">Attachments</a> or even a <a class=\"reference-link\" href=\"#root/_help_iPIMuisry3hd\">Text</a> note). The limit is approximately 374 MiB and it's determined by the <a class=\"reference-link\" href=\"#root/_help_cbkrhQjrkKrh\">Synchronization</a> protocol. Attempts to import such large files will be refused.\n\nDuring large imports or exports, memory consumption might spike but it will remain somewhere around the 2 gigabyte mark. Tested with a 2.4 GB database with ~21k notes.\n\n> [!IMPORTANT]\n> For the <a class=\"reference-link\" href=\"#root/_help_poXkQfguuA0U\">Desktop Installation</a>, there are two distinct import mechanisms:\n> \n> *   A quick import, from the <a class=\"reference-link\" href=\"#root/_help_oPVyFC7WL2Lp\">Note Tree</a>.\n> *   The import dialog (via right click in the note tree → _Import into note_ or from <a class=\"reference-link\" href=\"#root/_help_8YBEPzcpUgxw\">Note buttons</a>).\n> \n> When dealing with large files (multi-gigabyte), prefer using the import dialog as it has a special mechanism which makes sure that the file is read directly from disk rather than uploaded again.\n\n## Exporting the root note\n\nThe root note is the top-most note. Exporting it behaves just like any other note: right click on it in the <a class=\"reference-link\" href=\"#root/_help_oPVyFC7WL2Lp\">Note Tree</a> and select _Export_.\n\nStarting with v0.104.0, when a root note is imported, it will be imported as a child of your existing root note. This behavior makes sure that the import cannot change or overwrite your existing notes.\n\nYou can easily move the notes onto the root using the tree's <a class=\"reference-link\" href=\"#root/_help_yTjUdsOi4CIE\">Multiple selection</a> and delete the redundant root note.\n\n<table>\n    <thead>\n        <tr>\n            <th scope=\"col\">Before</th>\n            <th scope=\"col\">After</th>\n        </tr>\n    </thead>\n    <tbody>\n        <tr>\n            <td><ul><li>root<ul><li>one</li><li>two</li></ul></li></ul></td>\n            <td><ul><li>root (existing)<ul><li>root (from import)<ul><li>one</li><li>two</li></ul></li></ul></li></ul></td>\n        </tr>\n    </tbody>\n</table>\n\n> [!TIP]\n> Instead of exporting full ZIPs (including the root note), consider using [backups](#root/_help_ODY7qQn5m2FT)instead.
