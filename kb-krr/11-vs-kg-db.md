# Ontology 与知识图谱 / 数据库 schema / LLM 的区别

这是最容易混淆的一组概念。一句话定位：**Ontology 是"显式定义的概念+关系规则"，知识图谱是"数据+这套规则"，数据库 schema 是"只有约束没有推理的表结构"，LLM 是"隐式学习的统计知识"。**

---

## 一、Ontology vs 数据库 schema

两者都描述"结构"，但哲学完全不同：

| 维度 | Ontology | 数据库 schema |
|---|---|---|
| 目的 | 表达**领域知识**，支持推理 | 约束**数据存储**，保证一致性 |
| 语义基础 | 描述逻辑（开放世界假设） | 关系模型（封闭世界假设） |
| 未知的事实 | 视为"未知"，可后续补全 | 视为"不存在" |
| 推理 | ✅ 能推导未显式存储的事实 | ❌ 只存显式数据 |
| 冲突处理 | 允许部分矛盾、可含一致性检查 | 强约束，违反即拒绝 |
| 典型语言 | OWL 2 | SQL DDL |
| 表达力 | 等价类、逆角色、属性链、基数约束 | 主键、外键、NOT NULL、CHECK |
| 谁消费 | 机器+推理器 | 应用系统 |

**关键差异例子**：数据库里没存"张三有孩子"，查询"谁有孩子"就查不到；本体里若声明了 `hasChild` 的逆角色 `hasParent`，且存了 `lisi hasParent zhangsan`，推理器能自动推出 `zhangsan hasChild lisi`。

---

## 二、Ontology vs 知识图谱（Knowledge Graph）

知识图谱 = **Ontology（schema 层）+ 实例数据 + 推理/规则引擎**。两者是"骨架与整体"的关系：

| 维度 | Ontology | 知识图谱 |
|---|---|---|
| 层次 | 模式层（TBox/RBox） | 模式层 + 数据层（ABox）|
| 内容 | 类、属性、公理、规则 | 实体、关系、属性值 + 上述公理 |
| 产物 | .owl / .ttl 本体文件 | 图数据库 / 三元组库中的整图 |
| 例子 | 定义 `Person ⊑ ∃hasName` | 具体实例 `:zhangsan :hasName "张三"` |
| 规模 | 小（几百~几万公理） | 大（可到亿级三元组） |

> 业界常见误区：很多"知识图谱项目"只用了 RDF + 手工规则，没启用 OWL 推理。**没有 Ontology 层的知识图谱只是"数据库"；有了它才是"知识"——因为能推导出未显式存储的事实。**（详见 [[10-ontology]]）

---

## 三、Ontology vs LLM（大模型）

这是当前最热的话题。两者代表**知识的两种形态**：

| 维度 | Ontology | LLM |
|---|---|---|
| 知识形态 | **显式**（写死的公理） | **隐式**（参数里的统计规律） |
| 可靠性 | 可证明、可解释、可审计 | 概率性、有幻觉、不可完全解释 |
| 更新 | 精确、慢、需人工/工具维护 | 重训练或 RAG 更新 |
| 推理 | 逻辑演绎（保证正确） | 类比/归纳（可能出错） |
| 表达 | 需要专家形式化 | 自然语言，门槛低 |
| 维护成本 | 高（建模难） | 低（喂语料） |
| 擅长的场景 | 医疗/法律/规范等**高确定性**领域 | 开放问答、文本理解、创意生成 |

**结论不是二选一，而是互补**：详见 [[72-llm]]。

---

## 四、四者关系总览

```
数据库 schema  ──只约束存储，无推理──┐
                                     ├─→ 知识图谱 = Ontology + 数据 + 推理
Ontology（显式知识）──提供语义与推导──┘
                                     └─→ LLM（隐式知识）＝ 另一种知识载体，
                                          可与 Ontology 双向增强
```

| 概念 | 一句话记忆 |
|---|---|
| **Ontology** | "知识的说明书 + 推理规则" |
| **知识图谱** | "Ontology + 一堆事实" |
| **数据库 schema** | "只有表结构约束，不会思考" |
| **LLM** | "用参数记住了很多知识，但会胡说" |
