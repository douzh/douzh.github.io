# 描述逻辑 DL：本体语言的数学根基

## 一句话定位

**描述逻辑（Description Logic, DL）是一阶逻辑的"可判定子家族"，是 OWL 2 背后真正的数学。** 它用"概念（Concept）+ 角色（Role）+ 个体（Individual）"三样东西，把"领域知识"写成能被计算机自动推理的形式。你看到的所有 TBox / RBox / ABox / SROIQ，本质都是 DL 的语法切片。

---

## 一、三个基本构件

| 构件 | 英文 | 通俗理解 | 例子 |
|---|---|---|---|
| **概念（类）** | Concept / Class | 事物的集合 | `Man`（男人）、`Person`（人）|
| **角色（属性/关系）** | Role / Property | 个体之间的二元关系 | `hasChild`（有孩子）|
| **个体** | Individual | 具体对象 | `zhangsan`（张三）|

> 记忆：**概念管"是什么"，角色管"跟谁有关系"，个体管"具体是谁"**。

---

## 二、概念构造子（语法）

DL 用有限几种构造子把基本概念组合成复杂概念（相当于"描述逻辑的运算符号"）：

| 构造子 | 记法 | 含义 | 例子 |
|---|---|---|---|
| 顶概念 | `⊤` | 全集（所有个体） | |
| 底概念 | `⊥` | 空集（没有个体） | |
| 交集 | `C ⊓ D` | 既是 C 又是 D | `Man ⊓ Parent`（当爹的男人）|
| 并集 | `C ⊔ D` | 是 C 或 D | `Cat ⊔ Dog`（猫或狗）|
| 补集 | `¬C` | 不是 C | `¬Woman` |
| 存在限制 | `∃R.C` | 存在某个 R 关系到 C 的个体 | `∃hasChild.Person`（有个孩子是人）|
| 全称限制 | `∀R.C` | 所有 R 关系到的个体都在 C 里 | `∀hasChild.Human`（孩子全是人）|
| 基数限制 | `≥n R` / `≤n R` | 至少有/至多有 n 个 R 关系 | `≥2 hasChild`（至少俩孩子）|
| 限定基数 | `≥n R.C` | 至少有 n 个 R 关系到 C | `≥2 hasChild.Daughter`（至少俩闺女）|
| 枚举 | `{a,b,c}` | 恰好这些个体 | `{Beijing}` |

## 三、ALC → SROIQ 的扩展路径

DL 是一个**家族**，名字的每个字母代表一种"能力加成"：

| 逻辑 | 在上一级上加了什么 | 说明 |
|---|---|---|
| **ALC** | — | 基础逻辑（Attributive Concept Language with Complements）：交并补+存在/全称 |
| **+S** | 传递角色（S 源自 ALC + 传递） | 能表达 `partOf` 可传递 |
| **+R** | 角色层级（Role hierarchy） | 子角色：`hasSon ⊑ hasChild` |
| **+O** | 单例（Nominals） | 用个体直接定义类：`{Beijing}` |
| **+I** | 逆角色（Inverse roles） | `hasChild⁻¹ = hasParent` |
| **+Q** | 限定基数（Qualified number restrictions） | `≥2 hasChild.Daughter` |
| **= SROIQ** | 以上全加 + 复杂角色/属性链 | OWL 2 DL 采用的逻辑 |

> 命名规律：**每个字母 = 一种表达能力，字母越多表达力越强，但推理复杂度也越高。** SROIQ 是 DL 家族里"表达力与可判定性"的平衡顶点，这也是 OWL 2 DL 选它的原因。

---

## 四、语义：怎么知道一句话是"真"的

DL 的语义用一个**解释（interpretation）**定义：

```
I = ( Δ^I , ·^I )
```

- `Δ^I`：论域（一个非空个体集合，相当于"世界"）
- `·^I`：解释函数，把每个概念映射为论域的子集，每个角色映射为论域上的二元关系

例如：`Δ^I = {张三, 李四, 小红}`；`Man^I = {张三}`；`hasChild^I = {(张三, 李四)}`。当 `zhangsan ∈ Man^I` 时，就说"张三是一个男人"在这套解释下为真。

**可满足（satisfiable）** = 存在至少一个解释让它成立；**蕴含（entailment）** = 在所有解释下都为真。推理器干的就是这两件事的自动判定。

## 五、知识库的三盒结构（DL 视角）

DL 把知识库写成 `KB = (TBox, RBox, ABox)`：

| 盒 | 装什么 | 公理例子 | 对应 OWL |
|---|---|---|---|
| **TBox** | 概念层级与等价 | `Man ⊑ Person` | `rdfs:subClassOf` |
| **RBox** | 角色性质 | `hasChild ⊑ hasRelative`、`Transitive(ancestorOf)` | 属性公理 |
| **ABox** | 个体事实 | `Man(zhangsan)`、`hasChild(zhangsan, lisi)` | 个体断言 |

三者共同决定"能推出什么"（推理闭包）。详见 [[30-tbox]] / [[31-rbox]] / [[32-abox]]。

## 六、四大推理任务

| 推理任务 | 问题 | 例子 | 复杂度定位 |
|---|---|---|---|
| **可满足性** | 某概念有没有可能非空？ | `Man ⊓ Woman` 可满足吗？（否）| 核心，其余都规约到它 |
| **包含/分类** | C 是不是 D 的子类？ | `Man ⊑ Person` 成立吗？ | 由可满足性规约 |
| **一致性** | 整个 KB 有没有矛盾？ | ABox 说 `zhangsan` 既是 `Man` 又是 `Woman`？ | 由可满足性规约 |
| **实例化** | 某个体属于某概念吗？ | `zhangsan` 是 `Parent` 吗？ | 由可满足性规约 |

> 关键洞察：**DL 的四大推理任务全部可以规约到"概念可满足性"**——这是 DL 优雅的核心。推理器内部基本只做一件事：判断"有没有解释"。

---

## 七、复杂度：表达力是要付代价的

| 逻辑 | 可满足性复杂度 | 说明 |
|---|---|---|
| ALC | PSPACE | 基础就不便宜 |
| SHIQ | ExpTime | 加角色层级+逆+基数 |
| SROIQ（OWL 2 DL） | N2ExpTime | 最强，最贵 |
| OWL 2 EL（EL++） | P（多项式） | 牺牲表达力换速度 |
| OWL 2 QL（DL-Lite） | P / LOGSPACE 级查询 | 面向查询重写 |

**工程含义**：表达力越强，推理越慢。这就是为什么 OWL 2 提供 [[22-profiles]] 剖面，让你按需"降配"换效率。

---

## 记忆口诀

- **三构件**：概念（集合）、角色（关系）、个体（元素）；
- **四运算**：交、并、补、量词（∃/∀）+ 基数；
- **SROIQ**：传递、角色层级、单例、逆、限定基数；
- **四任务**：可满足性、分类、一致性、实例化——**全归约到可满足性**。

一句话总结：**描述逻辑 = 用"概念+角色"造句、用"解释"定义真假、用"可满足性"完成所有推理的形式语言；OWL 2 就是它披上 RDF 语法的工业外衣。**
